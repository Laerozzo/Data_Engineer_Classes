    "## Chapter 1: Working with Branches\n",
    "\n",
    "### 1.1 Why Use Branches?\n",
    "* **Branch**: An independent version/line of development within a repository.\n",
    "* **Default Branch (`main`)**: Represents the stable, production-ready \"ground truth\" system.\n",
    "* **Key Benefits**:\n",
    "  * Develop and test new features or bug fixes in isolation without destabilizing `main`.\n",
    "  * Enable multiple developers to work simultaneously on separate tasks.\n",
    "  * Compare states between branches (`git diff`) and merge completed work back into production.\n",
    "  * Each branch should serve a single, well-defined purpose (e.g., `ai-assistant`, `bug-fix`).\n",
    "\n",
    "### 1.2 Creating, Switching, Comparing, Renaming & Deleting Branches\n",
    "* **List all local branches**: `git branch` (the active branch is marked with `*`).\n",
    "* **Switch to an existing branch**: `git switch main`.\n",
    "* **Create a new branch (\"branching off\")**:\n",
    "  * Two steps: `git branch speed-test` followed by `git switch speed-test`.\n",
    "  * Single step: `git switch -c speed-test` (creates and switches immediately).\n",
    "* **Compare two branches**: `git diff main summary-statistics` (press `Space` to scroll, `q` to quit).\n",
    "* **Rename a branch**: `git branch -m feature_dev chatbot` (or `git branch -m new_name` while on the branch).\n",
    "* **Delete a branch**:\n",
    "  * `git branch -d chatbot`: Safe delete—succeeds only if `chatbot` has already been merged.\n",
    "  * `git branch -D chatbot`: Force delete—removes an unmerged branch (recovery is difficult; double-check before running).\n",
    "\n",
    "### 1.3 Merging Branches (`git merge`)\n",
    "* **Terminology**:\n",
    "  * **Source branch**: The branch containing the changes you want to merge *from* (e.g., `ai-assistant`).\n",
    "  * **Destination branch**: The branch you want to merge *into* (e.g., `main`).\n",
    "  * **Parent commits**: The latest commits on each branch being combined.\n",
    "* **Merge Commands**:\n",
    "  * Recommended workflow: Switch to destination (`git switch main`), then run `git merge ai-assistant`.\n",
    "  * Explicit two-argument form: `git merge ai-assistant main`.\n",
    "* **Fast-Forward Merge**: When `main` has not diverged since the feature branch was created, Git simply moves the `main` pointer forward to the last commit of the source branch."

    "## Chapter 2: Merge Conflicts & Collaborating with Remotes\n",
    "\n",
    "### 2.1 Understanding & Resolving Merge Conflicts\n",
    "* **When Conflicts Happen**: Two branches modify the same region of the same file (or add conflicting files), so Git cannot automatically decide which version to keep (`CONFLICT: Merge conflict in README.md`).\n",
    "* **Git Conflict Markers**:\n",
    "  ```text\n",
    "  <<<<<<< HEAD\n",
    "  Content from the current branch (e.g., main)\n",
    "  =======\n",
    "  Content from the incoming source branch (e.g., documentation)\n",
    "  >>>>>>> documentation\n",
    "  ```\n",
    "* **Resolution Workflow**:\n",
    "  1. Open the conflicted file in an editor (e.g., `nano README.md`).\n",
    "  2. Edit the file to keep the desired final text and **delete all conflict marker lines** (`<<<<<<<`, `=======`, `>>>>>>>`).\n",
    "  3. Save and exit (`Ctrl+O`, `Enter`, `Ctrl+X` in `nano`).\n",
    "  4. Stage the resolved file (`git add README.md`) and finalize the merge commit (`git commit -m \"Resolving README.md conflict\"`).\n",
    "\n",
    "### 2.2 Working with Remote Repositories (`git clone` & `git remote`)\n",
    "* **Remote Repository**: A copy of your repository hosted online (GitHub, GitLab, Bitbucket) or elsewhere on disk for backup and multi-developer collaboration.\n",
    "* **Cloning (`git clone`)**:\n",
    "  * `git clone https://github.com/datacamp/project`: Clones a remote repo and automatically registers it under the remote alias `origin`.\n",
    "  * `git clone /home/george/repo new_repo`: Clones a local repository into a directory named `new_repo`.\n",
    "* **Managing Remotes (`git remote`)**:\n",
    "  * `git remote`: Lists configured remote names (e.g., `origin`).\n",
    "  * `git remote -v`: Displays fetch and push URLs for every remote.\n",
    "  * `git remote add george https://github.com/george_datacamp/repo`: Registers an additional named remote.\n",
    "\n",
    "### 2.3 Fetching & Pulling from Remotes (`git fetch` vs. `git pull`)\n",
    "* **`git fetch origin` / `git fetch origin main`**: Downloads new commits and branches from the remote into remote-tracking references (`FETCH_HEAD`) **without** modifying or merging into your local working branches.\n",
    "* **`git pull origin` / `git pull origin dev`**: Performs `git fetch` followed immediately by `git merge` into your **currently active local branch**.\n",
    "* **Safety Rule**: Always commit or stash local changes before running `git pull` so Git does not abort with `Your local changes to the following files would be overwritten by merge`.\n",
    "\n",
    "### 2.4 Pushing to Remotes & Avoiding Non-Fast-Forward Rejections (`git push`)\n",
    "* **`git push <remote> <local_branch>`**: Uploads local commits to the remote repository (e.g., `git push origin main`).\n",
    "* **Handling `[rejected] main -> main (non-fast-forward)`**:\n",
    "  * Occurs when the remote branch has commits that your local branch lacks.\n",
    "  * **Fix**: Run `git pull origin main` first to integrate remote changes locally (avoiding `--no-edit` unless confident in the history), resolve any conflicts, and then run `git push origin main`.\n",
    "* **Pushing a New Local Branch**: Running `git push origin hotfix` creates the `hotfix` branch on the remote and sets up tracking (`origin/hotfix`)."
