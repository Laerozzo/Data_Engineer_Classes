    "## Chapter 1: Introduction to Version Control\n",
    "\n",
    "### 1.1 What is Version Control & Why Git?\n",
    "* **Version Control**: Processes and systems to manage changes to files, programs, and directories over time—especially useful for anything that changes frequently or needs to be shared.\n",
    "* **Core Capabilities**:\n",
    "  * Track files across different states and checkpoints.\n",
    "  * Combine different versions of files across collaborators.\n",
    "  * Identify who made specific changes, what changed, and when.\n",
    "  * Revert files back to previous working versions so nothing is permanently lost.\n",
    "* **Git**: Open-source, scalable, distributed version control system used across software engineering and data science projects, executed via the **shell (terminal)**.\n",
    "\n",
    "### 1.2 Essential Shell Commands & Navigating Repositories\n",
    "* `pwd`: Print working directory (displays your current folder path).\n",
    "* `ls`: List files and subdirectories in the current directory.\n",
    "* `cd <directory>`: Change directory (e.g., `cd archive`).\n",
    "* `git --version`: Verify that Git is installed and check its version.\n",
    "\n",
    "### 1.3 Creating & Inspecting Git Repositories (`git init` & `git status`)\n",
    "* **Git Repository (`repo`)**: A project directory containing files, subdirectories, and a hidden `.git/` storage directory that tracks all version history (**never manually edit `.git/`**).\n",
    "* **Initializing a Repository**:\n",
    "  * `git init <project-name>`: Creates a new directory and initializes an empty Git repo inside it.\n",
    "  * `git init`: Converts an existing project folder into a Git repository.\n",
    "* **Nested Repositories Warning**: Never initialize a Git repository inside another Git repository—having two `.git/` folders creates ambiguity over which repository tracks changes.\n",
    "* **`git status`**: Displays the current branch, staged files ready to be committed, modified unstaged files, and untracked files.\n",
    "\n",
    "### 1.4 The Core Git Workflow: Staging & Committing (`git add` & `git commit`)\n",
    "1. **Modify**: Create, edit, and save files in your working directory.\n",
    "2. **Stage (`git add`)**: Move modified/untracked files into the **staging area** (a holding area preparing the next snapshot):\n",
    "   * `git add README.md`: Stage a single file.\n",
    "   * `git add .`: Stage all modified and new files in the current directory and subdirectories.\n",
    "3. **Commit (`git commit`)**: Permanently record a snapshot of the staging area into the repository history:\n",
    "   * `git commit -m \"Adding a README.\"`: Commits staged changes with a concise, descriptive log message without opening a terminal text editor."

    "## Chapter 2: Viewing the Version History\n",
    "\n",
    "### 2.1 Git's Internal Commit Architecture & Hashes\n",
    "Every Git commit consists of three core objects:\n",
    "1. **Commit**: Stores metadata (author, timestamp, log message, parent commit pointer) and points to a root Tree.\n",
    "2. **Tree**: Tracks file and subdirectory names and locations (like a directory dictionary mapping filenames to Blobs or sub-trees).\n",
    "3. **Blob (Binary Large Object)**: Compressed snapshot of a file's contents.\n",
    "* **Git Hash (SHA-1)**: A 40-character hexadecimal identifier generated from object contents (e.g., `b22eb75a82a68b9c0f1c45b9f5a9b7abe281683a`). Identical files produce identical hashes, allowing Git to deduplicate storage and compare versions rapidly. You only need the first **8–10 characters** of a hash when referencing a commit.\n",
    "\n",
    "### 2.2 Inspecting Logs & Filtering History (`git log` & `git show`)\n",
    "* **`git log`**: Lists commits from newest to oldest (`Space` scrolls forward, `q` exits the pager).\n",
    "* **Filtering `git log`**:\n",
    "  * **Limit count**: `git log -3` shows only the 3 most recent commits.\n",
    "  * **Filter by file**: `git log report.md` or `git log -2 data/mental_health_survey.csv`.\n",
    "  * **Filter by date range**: `git log --since='Apr 2 2024' --until='Apr 11 2024'` (supports ISO dates `'2024-04-02'` and relative phrases like `'2 weeks ago'` or `'yesterday'`).\n",
    "* **`git show <hash>`**: Displays the commit metadata, log message, and full line-by-line diff for a specific commit hash (e.g., `git show c27fa856`).\n",
    "\n",
    "### 2.3 Comparing Versions (`git diff` & `HEAD`)\n",
    "* **`HEAD`**: Pointer referencing the latest commit on the currently checked-out branch (`HEAD~1` = parent commit, `HEAD~2` = grandparent commit).\n",
    "* **Common `git diff` Patterns**:\n",
    "  * `git diff` / `git diff report.md`: Compares unstaged working directory changes against the latest commit.\n",
    "  * `git diff --staged` / `git diff --staged report.md`: Compares staged changes against the latest commit.\n",
    "  * `git diff 35f4b4d 186398f`: Compares two commits using hashes (place older commit first, newer commit second).\n",
    "  * `git diff HEAD~1 HEAD`: Compares the second most recent commit against the latest commit.\n",
    "\n",
    "### 2.4 Restoring, Reverting & Unstaging Files\n",
    "* **Reverting an Entire Commit (`git revert`)**: Creates a *new* commit that undoes all changes introduced by a target commit (safe for shared histories):\n",
    "  * `git revert HEAD`: Reverts the latest commit and opens an editor for the commit message (`Ctrl+O`, `Enter`, `Ctrl+X` in `nano`).\n",
    "  * `git revert --no-edit HEAD`: Reverts the commit immediately using the default revert message.\n",
    "  * `git revert -n HEAD`: Reverts the changes into the staging area without creating a commit yet.\n",
    "* **Reverting a Single File (`git checkout`)**: `git checkout HEAD~1 report.md` restores `report.md` from `HEAD~1` into both the working directory and staging area (ready to commit).\n",
    "* **Unstaging Files (`git restore --staged`)**:\n",
    "  * `git restore --staged summary_statistics.csv`: Removes a single file from the staging area while keeping your local edits intact.\n",
    "  * `git restore --staged .`: Unstages all staged files."
